# Spring Boot មេរៀនទី ៨៖ Database Migration ជាមួយ Flyway/Liquibase

## ហេតុអ្វីត្រូវការ migration?
Schema របស់ database ជាផ្នែកនៃ application version។ បើ developer ប្ដូរ entity តែ production schema មិន update នោះ code និង data store មិនត្រូវគ្នា។ Migration ជា script/definition មាន version ដែលអាចតាមដាន និងដំណើរការដោយ repeatable process។

## Flyway គំនិតមូលដ្ឋាន
Flyway ជាទូទៅរក SQL migration តាមឈ្មោះ versioned file ដូចជា V1__create_books.sql ហើយរក្សាប្រវត្តិ migration ក្នុង schema history table។ Spring Boot អាច auto-configure migration integration ពេល dependency និង configuration ត្រូវបានបន្ថែម។ ពិនិត្យ docs/version នៃ dependency ដែល project ប្រើ។

~~~sql
CREATE TABLE books (
    id BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    title VARCHAR(200) NOT NULL,
    created_at TIMESTAMP NOT NULL
);
~~~

ប្រើ migration បន្ទាប់ដើម្បី add column ឬ index; កុំកែ migration ដែលបានរត់លើ shared environment រួច។ បង្ក migration ថ្មីដែល forward-compatible។

## Expand/contract deployment
សម្រាប់ deploy ដែលមាន app version ច្រើនដំណើរការជាន់គ្នា៖
1. Expand schema ដោយបន្ថែម field nullable/default និងរក្សា compatibility។
2. Deploy code ដែលអាចអាន/សរសេរទម្រង់ចាស់ និងថ្មីតាមចាំបាច់។
3. Backfill data ជា batch ដែលមាន limit។
4. ប្តូរ app ឱ្យប្រើ schema ថ្មី។
5. Contract schema ដោយលុប field ចាស់នៅពេលប្រាកដថាគ្មាន client ចាស់ប្រើ។

## Rollback
Database rollback មិនតែងតែសាមញ្ញ ព្រោះ data អាចបាត់/បម្លែងមិនអាចត្រឡប់។ គិតពី backup, forward-fix migration និង restore plan។ កុំសាក destructive migration លើ production ដោយគ្មាន review។

## លំហាត់
1. សរសេរ V1 migration បង្ក table books។
2. សរសេរ V2 បន្ថែម status ដែលមាន default សមស្រប។
3. ពន្យល់ថាហេតុអ្វីមិនគួរកែ V1 បន្ទាប់ពី shared database បានអនុវត្តវា។
4. រៀបចំ expand/contract plan សម្រាប់ rename column។
